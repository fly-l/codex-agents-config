# 项目长期记忆

把 Obsidian 知识库当作可审计的项目事实库，而不是聊天记录仓库。普通任务若不依赖历史信息且未产生持久事实，不要加载或写入记忆。

## 启用检查

从当前宿主已加载的项目级指令文件的 `知识体系` 章节读取：Codex 与 Pi 使用 `AGENTS.md`（`AGENTS.override.md` 优先），Claude Code 使用 `CLAUDE.md`。

- `启用` 必须为 `是`，`项目名称` 必须存在。
- 所有宿主统一优先使用 `PROJECT_MEMORY_VAULT`，其次使用项目的 `Vault根目录`。
- 缺少任一值时停止记忆操作；不猜路径、不创建替代目录、不写入秘密或个人敏感信息。

## 选择入口

- **回忆具体问题**：直接用 `memory_store.py search --module "<模块>" --query "<问题关键词>" --limit 3`；不要先审计整个项目。
- **了解整个模块**：才调用 `memory_store.py maintenance-audit --summary-only --module "<模块>"`，仅在返回摘要可用时读取其 `summary.path`。
- **记录**：阅读 [记录结构](references/schema.md)，按下方约束写入已确认或已验证事实。
- **初始化**、**审核 Hook 收件箱**、**更新当前状态**：只在对应任务需要时读取 [初始化流程](references/initialization.md)、[收件箱审核](references/inbox-review.md)、[当前状态](references/current-status.md)。
- **压缩、去重或摘要维护**：使用 `$project-memory-maintenance`，普通回忆不要顺带扫描全库。

## 回忆约束

详细检索规则见 [召回与复核](references/retrieval.md)。`search` 默认匹配 `any`，也支持 `--match all`；结果按精确 ID、命中关键词数量、标题/ID/模块命中权重、目标模块命中、更新时间和 ID 排序，命中位置只用于生成 `excerpt`。分页时把首轮返回的快照传入 `--expected-snapshot <snapshot>`；快照变化就停止并重新读取，不能把不同版本拼页。

默认只召回 `active|accepted|fixed`。首轮 3 条只是起点；跨模块、结果不足、关键约束未覆盖、来源冲突或依赖不明时继续按模块、路径、接口检索。字符预算只是输出截断，不等于 token 数或真实费用。

记忆是导航，不是源码证明；全局约定由项目指令文件始终生效，不依赖召回命中。读取命中记录的适用范围和来源，并用当前代码、测试或用户确认复核。明确区分当前实现、已确认但未落地的目标、历史决定和待验证问题；目标已确认不能使当前实现过早失效，当前实现也不能反过来否定目标。`proposed` 不作为当前事实，`superseded|deprecated` 只用于历史追溯。

## 记录约束

正式记录必须有稳定 ID、类型、状态、模块、来源和验证日期；来源应能由用户确认、源码位置、提交、测试或文档复核。措辞或证据补充更新原 ID；结论、范围或决策实质变化新建 ID 并以 `supersedes` 替代，保留旧记录和版本关系。

由当前任务指定的唯一写入代理串行执行 `upsert`；同一知识库的其他任务先协调写入时段。更新已有记录必须使用刚读取的 `--expected-fingerprint`，不匹配就重新读取并核对；更新时省略 `--verified-at` 保留原日期，新建时省略则默认当天。指纹版本和旧记录兼容规则以 [记录结构](references/schema.md) 为准，不能只换哈希就把旧摘要当成有效。子代理只提交候选、范围和证据。没有新证据不刷新 `verified_at`。写入后运行 `validate`；原子替换不提供跨任务事务保证。

只写已确认的决策、可复现且已修复的 Bug、已验证 API、稳定约定和当前环境事实。不得写入秘密、令牌、个人敏感路径、模型猜测、一次性日志或无来源结论。

## 初始化

按 [初始化流程](references/initialization.md) 完成结构、首批有来源事实、适用约定、当前状态和校验；创建空目录或索引不算完成。

## 审核 Hook 收件箱

Stop 只登记待审核会话元数据，不把聊天正文自动提升为权威记忆。按 [收件箱审核](references/inbox-review.md) 只处理与当前任务有关且能由源码、测试或用户确认复核的候选；证据不足保持待处理。

项目配置 `自动审核` 默认 `否`；开启时 SessionStart 只提示 pending 候选的有限元数据，不启动模型。当前主代理每次会话最多先审核 1 条与任务相关的候选；用户明确要求整理时才扩批。未初始化时自动审核不能代替初始化，信息不足的候选保持 `pending`。具体流程见 [收件箱审核](references/inbox-review.md)。

## 当前状态

仅在架构、关键约束或主线事项确实变化时，按 [当前状态](references/current-status.md) 更新短摘要。若 `自动加载：是`，SessionStart 注入的当前状态仍只是导航，不能替代原子记录、源码或测试；大型项目保留全局约束和模块链接，细节留在原子记录与模块摘要中。
