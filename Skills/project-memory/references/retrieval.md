# 召回与复核

## 检索步骤

命令中的脚本路径从已安装的 project-memory Skill 目录解析。

```bash
python "<Skill目录>/scripts/memory_store.py" \
  --vault-root "<Vault根目录>" --project "<项目名称>" \
  search --module "orders" --query "幂等 支付" --limit 3
```

- `--module` 可重复指定，使用与记录完全一致的模块名称；同时返回 `global` 规则和未分类旧记录。后者标记 `scope_needs_review: true`，必须先核实范围，不代表全局适用。
- 关键词以空格分隔，任一词命中 ID、标题、模块、来源或正文即成为候选；优先按命中相关性排序，再按更新时间排序。结果不是语义检索，需按业务别名、源码路径或接口名补充查询。
- 可以只指定模块，或省略模块跨分类按关键词搜索。检索覆盖项目各正式分类目录，不受首页展示数量限制；不扫描其他项目或整个 Vault。
- 默认只返回 `active|accepted|fixed`。每条最多返回 240 字符正文预览，预览不能代替完整适用范围；作出实现判断前读取相关记录原文。
- `--limit 3` 是首轮数量；存在未覆盖的关键约束时，使用返回的 `next_offset` 作为 `--offset` 继续取下一页，或缩小模块和关键词。`--max-chars` 默认限制整份 JSON 输出为 6,000 字符；一条也装不下时直接报错，需要提高上限。
- 分页期间由指定写入代理暂停变更同一知识库，避免结果顺序改变。没有命中不等于不存在约束；补查业务别名和相关源码，仍无依据则明确说明未找到可靠记忆。

跨模块任务分别覆盖相关模块、全局约束及公共接口，不以固定条数作为完成标准。查询已经覆盖这些范围，且没有会改变实现选择的未解决冲突时停止；确实无法验证的疑问单独标注，不循环扩大到无关知识。

## 摘要入口

```bash
python "<Skill目录>/scripts/memory_store.py" \
  --vault-root "<Vault根目录>" --project "<项目名称>" \
  maintenance-audit --module "orders"
```

读取输出的 `summary.path`，且仅在 `summary.usable: true` 时作为该模块完整导航。省略 `--module` 时检查项目级摘要；模块完整不意味着覆盖整个项目。`partial` 或过期摘要不能替代定向检索，但无需为一次普通召回立即重建摘要。

模块摘要包含该模块、`global` 及未分类旧记录，并只根据该范围内的权威记录判断变化。无关模块更新不使其过期；全局规则和相关记录变化会使其过期。摘要中的链接和来源 ID 用于继续定位事实，不作为源码有效性证明。

## 适用范围与变更复核

1. 对照任务的仓库、模块、分支或发布版本，阅读记录正文中的适用范围、源码路径、符号和验证基线。旧记录没有这些信息时以当前源码重新确认，不自动视为所有分支通用。
2. 指纹有效只说明知识输入未变化。修改关联路径、公共接口、依赖或配置时，依据记录中的提交基线和当前 diff 检查事实；读取相关源码，运行该变更本就需要的验证，不为每条记忆重复运行全部测试。
3. 区分当前实现和已确认目标。实现暂未符合新目标时记录差距；不得用旧代码否定用户已确认的变更，也不得把目标描述成已落地行为。
4. 结论仍有效时补充证据并更新验证日期；实质变化采用新 ID 和 `supersedes`。分支上的事实注明范围，未经主线验证不改写项目主线现状。
5. 无法取得源码或验证失败时，说明尚待验证并停止将该结论作为实现依据；不因时间陈旧直接废弃，也不在未复核时刷新验证日期。资料恢复后的相关任务再复核。

## 召回验收

用真实开发问题检查以下结果，而不只检查存储格式：较早但重要的规则仍能被检索；跨模块任务覆盖相关接口；`proposed` 和错误分支的结论不会被当成当前事实；源码已变化的记忆会被复核；超出首轮数量时能够继续检索。脚本测试只能证明筛选、分页和摘要失效行为，分支适用性与源码语义仍需按上述步骤核实。
