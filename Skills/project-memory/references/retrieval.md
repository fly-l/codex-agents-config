# 召回与复核

命令中的脚本路径从已安装的 project-memory Skill 目录解析，Vault 与项目配置先按主 Skill 的启用检查确认。

## 具体问题

```bash
python "<Skill目录>/scripts/memory_store.py" \
  --vault-root "<Vault根目录>" --project "<项目名称>" \
  search --module "orders" --query "幂等 支付" --limit 3
```

`--module` 可重复使用，模块名必须与记录一致；模块查询同时带上 `global` 和没有模块的旧记录，后者标记为需要复核，不代表全局适用。`--query` 应使用问题中的业务别名、源码路径、接口名和关键约束，而不是只依赖一个标题。也可省略模块做有明确关键词的跨模块查询。

## 匹配、排序与分页

- `--match any` 为默认值，任一关键词命中即可；`--match all` 要求所有关键词命中。
- 搜索覆盖所有正式分类目录，不受 `索引.md` 展示数量限制，默认只返回 `active|accepted|fixed`。
- 结果依次按精确 ID、命中关键词数量、标题/ID/模块命中权重、目标模块命中、更新时间和 ID 排序；命中位置不参与排序，只用于让 `excerpt` 围绕命中位置截取，不能只返回正文开头。
- 首轮默认 `--limit 3`。关键约束未覆盖时使用返回的 `next_offset` 分页或缩小模块、路径和接口范围；不能因取满 3 条就停止。
- 首轮返回的快照用于一致性分页。后续请求传入 `--expected-snapshot <snapshot>`；快照不一致就停止、重新读取首轮，不把不同版本的页拼在一起。
- `--max-chars` 只限制序列化输出的字符数；字符预算不等于模型 token 数，也不等于真实费用。一条结果无法容纳时提高预算或缩小查询，不截断到无法复核的程度。

没有命中不等于没有约束：补查业务别名、源码路径和接口名，并结合当前代码和测试判断是否真的不存在可靠记忆。跨模块任务分别覆盖相关模块、全局约定和受影响公共接口。

## 模块概况

只有任务需要了解整个模块时调用：

```bash
python "<Skill目录>/scripts/memory_store.py" \
  --vault-root "<Vault根目录>" --project "<项目名称>" \
  maintenance-audit --summary-only --module "orders"
```

仅当返回 `summary.usable: true` 时读取 `summary.path`；`partial`、过期或范围不符的摘要不能作为完整入口。模块摘要只覆盖目标模块、`global` 和无模块旧记录，不代表全项目完整。普通具体问题不要用全库审计替代定向搜索。

## 复核与停止

读取命中记录原文，核对仓库、模块、分支、版本、源码符号、来源和验证基线。用当前代码、测试或用户确认分别判断当前实现、已确认但未落地的目标、历史决定和待验证问题。指纹只说明知识输入是否变化，不证明源码仍与记录一致；修改关联路径、公共接口、依赖或环境配置时必须重新复核。

默认不采用 `proposed`；`superseded|deprecated` 只用于追溯变更原因。结论仍有效时补充证据并更新验证日期；实质变化新建记录并设置 `supersedes`。若无法取得源码或验证失败，标为待验证并停止把它作为实现依据，不因日期陈旧自行废弃。

当相关模块、全局约束和公共接口已有依据，且没有会改变实现选择的未解决冲突时停止；否则继续定向查询并报告仍未覆盖的范围。
