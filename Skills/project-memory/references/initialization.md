# 初始化流程

仅在项目配置已启用、项目名称存在且知识库不存在或只有结构时使用。初始化的完成条件是：项目概况、主要模块导航、运行与验证方式、核心约定和当前状态都有真实来源；只创建空目录、空索引或占位笔记不算完成。

1. 从当前 `SKILL.md` 所在目录解析脚本路径，使用 `PROJECT_MEMORY_VAULT` 或项目配置的 `Vault根目录`；缺少路径就停止，不猜路径。先运行以下命令创建缺失结构，不覆盖已有笔记：

   ```bash
   python "<project-memory Skill目录>/scripts/memory_store.py" \
     --vault-root "<Vault根目录>" --project "<项目名称>" init
   ```
2. 读取当前项目已加载的指令、README、构建配置、关键入口和相关源码，定向确认用途、主要模块、技术栈、运行与验证方式及适用约定。不要扫描整个 Vault，也不要为填满分类编造记录。
3. 阅读 [记录结构](schema.md)，按记录流程写入首批原子笔记：每条都要有稳定 ID、来源、模块、状态和验证日期。区分当前实现与已确认但尚未落地的目标；只有有依据时才记录决策、Bug 或 API 经验。
4. 将项目适用的已确认约定写入 `约定/`，包括反过度工程和反防御性编程规则，并标注权威指令文件来源。记忆侧保留适用说明，不复制一份会与指令长期分叉的独立全文。
5. 按 [当前状态](current-status.md) 更新短摘要，链接首批原子笔记并保留仍有效的内容。最后运行 `validate`，确认记录、索引和当前状态有效。

报告新增或更新的记录、证据和未能核实的内容。若资料不足，明确报告初始化未完成及缺少的资料；不要把结构创建成功说成初始化完成。写入仍由单一代理串行执行，子代理只提交候选和证据。
