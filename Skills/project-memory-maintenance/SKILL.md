# 项目记忆维护

通过“短活跃索引 + 可追溯历史记录 + 按模块摘要”控制召回上下文。维护不会删除正式记录：旧事实保留在原文件中，标记为 `superseded` 或 `deprecated` 后移出活跃索引。规模较大的模块可以使用独立摘要，项目摘要仍负责全局导航。

## 启用检查

复用 `project-memory` 的项目配置：`启用` 必须为 `是`，`项目名称` 必须存在。Codex 从项目级 `AGENTS.md` 读取并优先使用 `CODEX_MEMORY_VAULT`；Claude Code 从项目级 `CLAUDE.md` 读取并优先使用 `CLAUDE_MEMORY_VAULT`；两者均以 `Vault根目录` 作为次选。缺失任一必要值时停止，不猜测路径。

## 维护流程

脚本路径分别从本 `SKILL.md` 和已安装的 `$project-memory` 目录解析，不要假设当前项目包含 `Skills/` 源码目录。

1. 先运行 `<project-memory Skill目录>/scripts/memory_store.py maintenance-audit`；只维护单个模块时追加一个 `--module "<模块>"`。省略时审计项目全量；指定模块时只对该模块、`global` 和无模块旧记录计算摘要有效性。审计会读取记录正文，并将正文、模块、状态、来源和验证日期等知识输入纳入指纹，但不会把全部正文注入模型，也不会修改知识库。输出应包含摘要的 `path` 和 `module`。
2. 根据审计结果决定是否维护：待复核收件箱、重复或冲突候选、当前状态或索引接近限制，以及任务需要但摘要或模块摘要缺失、过期或覆盖范围不符，都是维护信号。活跃记录少于 60 条不能单独作为跳过理由；日期陈旧只是复核提示，内容指纹只能发现知识输入发生变化，不能证明源码仍然有效。
3. 需要定向查找记录时，按 [合并规则](references/consolidation.md) 使用 `memory_store.py search`；它搜索所有分类目录，不受首页 60 条限制，默认只返回 `active`、`accepted`、`fixed`，首轮默认 `--limit 3`、`--offset 0`、`--max-chars 6000`，必要时可分页或扩大范围。`--module` 可重复；模块查询还会带上 `global` 和无模块旧记录，后者必须复核适用范围。`--query` 可省略或为空，但至少要提供非空关键词或一个模块。普通召回入口遵循 `project-memory` Skill。
4. 需要语义合并时，再运行本 Skill 的 `scripts/memory_maintenance.py audit`，可追加单个 `--module "<模块>"` 缩小候选范围。每批默认最多检查 12 条同类型、同模块候选；正文合计接近 24,000 字符时提前分批。
5. 用当前代码、测试、提交或用户确认复核候选。`proposed` 记录不进入权威索引或摘要，但仍可被审计；不得通过合并自动提升为 `accepted`、`active`，经用户确认并复核后按“记录”流程处理。无法确定仍然有效的内容不要合并，可标记为待复核但不得编造结论。
6. 写入由指定的单一代理串行执行；子代理只提供候选和证据，不直接修改知识库。纯措辞或格式调整沿用原 ID 更新；实质决策改变时创建新 ID，并通过 `upsert --supersedes <旧ID>` 建立替代关系。存储脚本会保留旧文件，将其移入历史索引。
7. 用 `write-summary` 生成摘要正文不超过 6,000 字符、80 行且带来源 ID 的摘要。省略 `--module` 写入项目级 `知识摘要.md`；指定单个模块时写入 `模块摘要/<模块名 UTF-8 完整 SHA-256>.md`。只有覆盖当前审计范围且 `coverage: complete` 的摘要才可作为对应范围的完整入口；`partial` 不能作为完整入口，模块完整也不代表全项目完整。模块规模较大时，`当前状态.md` 只保留全局约束和模块导航，不要求一份项目摘要容纳所有记录。摘要 frontmatter 还包含来源元数据和输入指纹，不计入上述正文限制。
8. 升级后旧版本摘要可能因指纹算法或覆盖状态变化一次性被标记为过期；按需重写对应摘要，旧首页若仍显示 `proposed` 可运行 `rebuild-indexes` 清理。该兼容处理不修改原子记录格式，也不要求迁移旧原子记录。
9. 最后运行 `validate`，并按相同范围再次运行 `maintenance-audit`，报告压缩前后的活跃记录数、活跃索引字符数、历史记录数、摘要 `path`/`module`、跳过的冲突以及待复核项。

## 约束

- 不删除原子记录，不覆盖来源，不把未经验证的会话候选提升为正式记忆。
- 不跨项目、记录类型或无关模块合并；模块范围的审计和摘要只纳入匹配模块、`global` 与无模块旧记录，无模块记录不得未经复核就视为模块事实。
- `proposed` 记录不得通过合并自动提升为 `accepted`、`active` 或进入权威摘要；经用户确认并复核后按“记录”流程处理。它们仍保留在审计范围内，冲突记录先按来源优先级核实。
- 普通召回由 `project-memory` Skill 统一决定入口和范围；仅当用户追溯旧决定或变更原因时才读取 `历史索引.md`。
- 定时任务必须先审计；摘要在确有需要时缺失或过期、存在待复核项或重复候选时应继续维护，不能因记录少于 60 条就跳过。无变化时快速结束。
- 已处理或忽略的收件箱只允许移动到可恢复的归档目录，不直接删除。
