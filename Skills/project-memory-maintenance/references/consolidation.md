# 语义合并规则

## 候选选择

先用存储工具做有界检索，再运行深度候选审计；两个命令都不会自动合并或写入：

```bash
python "<project-memory Skill目录>/scripts/memory_store.py" \
  --vault-root "<Vault根目录>" \
  --project "<项目名称>" \
  search \
  --query "<关键词，可为空>" \
  --module "<模块>" \
  --limit 3 \
  --offset 0 \
  --max-chars 6000
```

`--module` 可以重复。`search` 查询所有分类目录，不受 `索引.md` 最多 60 条的展示限制；默认只返回 `active`、`accepted`、`fixed`，首轮默认 3 条、6,000 字符，可用 `--offset` 分页或扩大 `--limit`。指定模块时，结果还包括 `global` 和无模块旧记录；无模块记录只是待复核候选，不能直接当作该模块事实。`--query` 可以省略或传空值，均表示不按关键词缩小，但至少要提供非空关键词或一个模块。

```bash
python "<本 Skill目录>/scripts/memory_maintenance.py" \
  --vault-root "<Vault根目录>" \
  --project "<项目名称>" \
  audit \
  --module "<模块>"
```

省略 `--module` 时审计项目全量；指定后只审计该模块、`global` 与无模块旧记录。审计会读取正文计算指纹，但不会把全量正文注入模型。`proposed` 记录不进入权威索引或摘要，但仍可被审计和列为候选；不得通过合并自动提升为 `accepted`、`active`，经用户确认并复核后按“记录”流程处理。

优先处理以下候选：

1. 相同 `type`、相同 `module`，且描述同一接口、约定、架构边界或 Bug 根因的记录。
2. 新记录明确替代旧记录，但旧记录仍处于活跃状态。
3. 多条记录只有时间、措辞或局部示例不同，核心约束相同。
4. 长期未验证且与当前代码可能冲突的活跃记录；日期陈旧只触发复核，不足以单独证明内容失效，也不能直接合并。

不要仅因标题相似就合并。独立决策、不同适用范围、需要分别追溯的事故与尚未解决的冲突应保持独立。

模块审计沿用“匹配模块 + `global` + 无模块旧记录”的范围。无模块旧记录需要结合代码和来源确认是否仍适用，确认后再决定保留原范围、补模块或拆分记录。

## 摘要记录

摘要记录沿用原有 `type`，不要新增通用 `summary` 类型。优先更新已有的稳定主题 ID；没有合适 ID 时，为该主题创建一个可长期复用的 ID。

正文只保留：

- 当前有效结论；
- 适用模块和边界；
- 会改变实现选择的例外；
- 必要的验证方式；
- 被合并记录的 ID 或其他可核验来源。

不要复制完整历史、长日志、聊天内容和重复示例。历史原因留在被替代的原子记录中。

示例命令：

```bash
python "<project-memory Skill目录>/scripts/memory_store.py" \
  --vault-root "<Vault根目录>" \
  --project "<项目名称>" \
  upsert \
  --kind architecture \
  --id "ARCH-memory-retrieval" \
  --title "项目记忆召回边界" \
  --body-file "<已复核摘要文件>" \
  --status active \
  --source "代码、测试或用户确认" \
  --module "project-memory" \
  --supersedes "ARCH-memory-index-v1" \
  --supersedes "ARCH-memory-index-v2"
```

`upsert` 会保留旧文件，将旧状态改为 `superseded`，记录 `superseded_by`，并分别重建 `索引.md` 与 `历史索引.md`。

## 知识摘要

摘要正文必须简短列出当前有效知识，并让每个要点引用至少一个来源记录 ID。完成语义合并后写入：

```bash
python "<本 Skill目录>/scripts/memory_maintenance.py" \
  --vault-root "<Vault根目录>" \
  --project "<项目名称>" \
  write-summary \
  --body-file "<摘要正文>" \
  --source-id "<活跃记录ID>" \
  --coverage complete
```

省略 `--module` 时写入项目级 `知识摘要.md`；指定单个 `--module "<模块>"` 时写入 `模块摘要/<模块名 UTF-8 的完整 SHA-256>.md`。工具默认限制摘要正文为 6,000 字符、80 行，并保存对应范围的输入指纹；指纹纳入正文、模块、状态、来源和验证日期等知识输入。摘要审计返回生成文件的 `path` 和 `module`；模块摘要只对该模块、`global` 与无模块旧记录计算有效性。

只有确认摘要覆盖当前范围的稳定知识时才设置 `--coverage complete`。`partial` 只能表示局部或暂不完整的摘要，不能作为完整入口；模块摘要标记为 `complete` 也不代表全项目摘要完整。摘要指纹用于发现知识输入发生变化，不代表源码、测试或外部事实已经验证；任何候选仍须按来源优先级复核。项目规模较大时，`当前状态.md` 保留全局约束和模块导航，细节放在原子记录与模块摘要中，不要求一份项目摘要容纳全部记录。frontmatter 的来源 ID、覆盖范围和指纹不计入摘要正文限制。

摘要缺失或过期只有在当前任务需要它作为召回入口时才构成维护触发；待复核项、重复候选或范围不符同样需要处理。活跃记录少于 60 条不能作为单独的跳过条件。

升级后旧版本摘要可能因指纹算法或覆盖状态变化一次性被标记为过期；按需重写对应摘要，旧首页若仍显示 `proposed` 可运行 `rebuild-indexes` 清理。该兼容处理不修改原子记录格式，也不要求迁移旧原子记录。

已处理或忽略超过 30 天的收件箱条目可先预览、再做可恢复归档：

```bash
python "<本 Skill目录>/scripts/memory_maintenance.py" \
  --vault-root "<Vault根目录>" \
  --project "<项目名称>" \
  archive-inbox --older-than-days 30
```

确认候选无误且当前任务授权整理写入时，追加 `--apply`。此命令只移动文件到 `收件箱/归档/<年份>/`，不删除。

## 写入与分批停止条件

- 每批最多 12 条候选，正文合计约 24,000 字符时继续拆批。
- 一批只处理一个 `type + module + 主题`。
- 任何来源冲突、适用范围不明或代码验证失败都应停止该主题的写入，并将其列为待复核项。
- 写入由指定的单一代理串行执行；子代理只返回候选与证据，不直接写入。纯措辞或格式调整沿用原 ID 更新；实质决策改变时创建新 ID，并通过 `upsert --supersedes <旧ID>` 建立替代关系。
- 达到维护目标后停止；不要为追求更少记录继续合并有独立价值的事实。

## 定时运行提示词

为 Codex 自动化使用以下意图即可，不在 Skill 中固定调度频率：

> 使用 $project-memory-maintenance 维护当前项目知识库。先按需要执行项目或模块审计；检查摘要缺失/过期、范围不符、待复核项、同主题冗余和状态链。按小批次复核并合并，不得删除历史记录；写入由单一代理串行完成，子代理只提供候选与证据。完成后验证并报告范围、摘要 path/module、前后指标和遗留待复核项；没有变化时直接结束。

通常每周或每两周运行一次即可；实际频率取决于记忆写入速度。创建自动化时由用户明确时区和运行时间。
